# 다음 계획: 무료 GPU 학습과 음성 연결

기준: Kaggle 무료 T4, 덕 2,048마리 동시, 약 390회(iteration)/시간, 한 세션 최대 약 10시간,
무료 한도 주 30시간. 이번 주는 세션 2 이후 약 8.5시간 남고, 10월 31일 오전 9시(한국 시간)에 30시간으로 채워져요.

## 1. 진짜 강화학습이 필요한 것 / 필요 없는 것

| 행동 | 새 학습 필요? | 이유 | 예상 무료 GPU |
|---|---|---|---|
| 걷기·돌기·멈추기 | 속도만 | 지금 실제 속도가 명령의 절반. 세션 2(오늘 22시쯤 끝)가 바로 이 문제를 고치는 중 | 세션 2 결과 보고 필요하면 1회(10시간) 더 |
| 고개 돌리기 | 아니요 | v8이 이미 배움 | 0 |
| 일어나기 | 아니요 | v8이 이미 배움(공개 평가: 자세별 94–100% 일어남) | 0 |
| 춤 | **예 (크게 하려면)** | 지금은 이미 아는 작은 동작(몸 ±12°, 고개, 돌기)을 이어 붙인 것. 몸 위아래로 튕기기(앉았다 서기)는 v8이 못 배움 | 아래 A 또는 B |
| 공 따라가기 | 시뮬레이션은 아니요 | 공 위치만 알면 지금 정책+조종 규칙으로 따라감. 실제 로봇에 필요한 건 학습이 아니라 **공을 보는 카메라/인식** | 0 (카메라 문제) |
| 공 차기 | 이미 있음 | Pollen 실제 로봇에 `kick_left/right` 스킬이 있고, 저장소에 BallKick 학습 환경도 있음 | 직접 다시 학습하면 발마다 약 10시간 |

### 춤을 진짜로 가르치는 두 가지 방법

- **A. 몸 자세 범위 넓히기 (싸고 안전, 추천)** — v8에서 이어서, 서 있을 때 몸 기울기 범위를 ±12° → ±20°로,
  몸 높이(위아래 2–3 cm 튕기기)에 보상을 줘서 배우게 해요. 걷기·일어나기는 그대로 지키면서 1,500–2,000회.
  **약 4–5시간 (한 세션의 절반).** 그 뒤 지금 만든 안무 코드를 그대로 쓰면 춤이 훨씬 커져요.
- **B. 춤 전용 정책 (모션 따라 하기)** — 안무 키프레임(몸·고개·발 자세의 시간표)을 만들어 그 동작을 따라 하도록
  처음부터 학습해요(저장소의 ground_pick·spin 처럼 박자(phase) 명령을 쓰는 방식). 3,000–5,000회,
  **약 8–13시간 (세션 1회 이상)**, 실패하면 한 번 더. 동작은 화려해지지만 춤 하나에 정책 하나라 실제 로봇에선
  춤출 때만 정책을 바꿔 끼워야 해요.

### 롤러스케이트 더 잘 타기 (준비 완료, `../microduck_rl_training/kaggle/roller_session/`)
- 지금은 Pollen 공개 `roller.onnx` 를 그대로 써요(`roller_demo.py`). 속도 폭이 좁고(명령 0.3–0.6 → 실제 0.27–0.34 m/s), 0.2 이하는 서 버려요.
- 준비한 노트북: 같은 롤러 작업(`Mjlab-Velocity-Flat-MicroDuck-Rollers`)에서 공개 roller.onnx 를 체크포인트로 바꿔 **이어 학습**(warm start).
  박스 CPU 시험에서 변환·내보내기·이어 학습이 모두 되는 걸 확인했어요. 예상 2–4시간이면 변화가 보이고, 자동 정지는 10시간.
- 춤(A)과 같은 주에 하려면 각각 5시간 정도로 나눠요 (주 30시간 무료).

### 추천 순서 (무료 한도 안)
1. 오늘 밤: 세션 2 결과로 걷기 속도를 확인 (GPU 0시간, 내일 9:30 루틴).
2. 10/31 이후 첫 세션(≈10시간): 세션 2가 성공했다면 그 결과에서 **A(춤용 몸 자세 넓히기)** 를 4–5시간,
   남은 시간은 속도 다듬기. 끝나면 이 폴더의 `run_demo.py --ckpt 새체크포인트` 로 같은 데모를 다시 찍어 전후 비교.
3. 같은 주 남는 시간 또는 그다음 주: **롤러 warm start 세션** (5–10시간).
4. 그다음: A로 부족하면 B를 한 세션.

## 2. 실제 로봇에 한국어 음성 붙이기 (무료)

```
마이크 → (말 구간 자르기 VAD) → faster-whisper small, int8 (무료, 오프라인)
       → korean_commands.parse / parse_fuzzy → robotd JSON-RPC 명령 (/run/robotd.sock)
          · 걷기/돌기: robot.move {vx, vy, vyaw} 를 20–50 Hz로 계속 보냄, 멈춰 = robot.stop
          · 춤: behaviors.Dance 안무를 같은 방식으로 시간에 맞춰 송신 (고개·몸 명령 통로 확인 필요)
          · 일어나기: 정책이 자동으로 함 (명령 불필요)
          · 공 차기: robot.do {skill: kick_left/kick_right}
```

- 덕 본체(RK3566, RAM 1 GB)에서는 Whisper small(이 박스에서 명령 하나 약 1초, 메모리 약 1 GB 이상)을
  돌리기 어려워요. 처음에는 **같은 와이파이의 PC나 노트북**에서 음성 인식을 돌리고 명령만 덕에게 보내는 게
  현실적이에요. 덕 안에서 돌리려면 whisper tiny/base 로 줄이고 정확도를 다시 재야 해요.
- 명령 어휘를 Whisper에 미리 알려 주는 힌트로 합성 음성 정확도가 약 92%까지 올라왔어요. 실제 사람 목소리,
  아이 목소리, 시끄러운 방에서는 다시 재야 해요.
- 안전: 알아듣지 못하거나 애매하면 움직이지 않고, "멈춰"는 언제나 가장 먼저 처리해요.
- 공 따라가기를 실제로 하려면 공 위치를 알아야 해요. 덕 머리에 작은 카메라 + 색깔(주황 공) 검출 정도면
  무료로 시작할 수 있어요. 지금 덕에 카메라가 있는지부터 확인이 필요해요.
